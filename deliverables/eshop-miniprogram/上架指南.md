# 上架微信小程序 · 操作清单

代码已经写完，接下来是"代码之外"的流程。按顺序做，最快 **1 周**能上线，一般 2–3 周（卡点基本都在资质和备案，不在代码）。

---

## 第 0 步：确认主体资格（最容易白忙的一步）

| 主体类型 | 能否做电商交易 | 说明 |
|---|---|---|
| 企业 / 个体工商户 | ✅ 可以 | 需要营业执照，认证费 300 元/年 |
| 个人 | ❌ 不可以 | 个人主体小程序**无法开通微信支付、无法上架交易类目** |

如果要卖货，必须注册**企业或个体工商户**主体的小程序（mp.weixin.qq.com → 立即注册 → 选小程序 → 企业主体）。

---

## 第 1 步：ICP 备案（2024 起强制，先做这个）

小程序后台 → **设置 → 小程序备案**，按指引填主体信息、负责人信息、人脸核验。

- 耗时：**1–20 个工作日**（通常 3–7 天）
- **没备案无法提交审核**，所以这是第一优先级，注册完账号立刻发起
- 备案期间可以同步做下面的开发配置，不冲突

## 第 2 步：完善小程序信息与服务类目

1. **基础信息**：名称（全网唯一，重名需商标授权）、头像、简介（不含"最""第一"等极限词）
2. **服务类目**（小程序后台 → 设置 → 基本设置 → 服务类目）：

| 你卖什么 | 选什么类目 | 需要什么资质 |
|---|---|---|
| 自营百货 / 数码 / 家居 | 电商平台 - 商家自营 | 营业执照 |
| 食品（含咖啡豆） | 食品 - 食品销售 | **《食品经营许可证》** |
| 化妆品 / 保健品 / 医疗器械 | 对应类目 | 对应许可证，**审核最严** |

> 建议：首版先上**不需要特殊资质**的品类（数码配件、家居日用），食品等特殊品类等证办下来再加。类目和商品不符是高频驳回原因。

## 第 3 步：代码侧配置

1. 开发者工具 → 导入项目 → 填入你的 **AppID**（替换 `project.config.json` 里的 `touristappid`）
2. 开通云开发 → 复制环境 ID → 填进 `miniprogram/app.js` 的 `ENV_ID`
3. 云函数逐个右键「上传并部署：云端安装依赖」：`login → product → cart → order → pay → payCallback`
4. 建集合 `users / products / carts / orders`，权限一律设「仅管理端可读写」

## 第 4 步：隐私指引（不做会导致线上无法上传图片）

小程序后台 → **设置 → 服务内容声明 → 用户隐私保护指引** → 更新，勾选：

- **相册**（含摄像头）：用于上传商品图片 / 头像

代码里已经做了处理（`utils/cloud.js` 的 `ensurePrivacy`），但后台不声明，调用仍会失败。

## 第 5 步：微信支付（企业主体）

1. 申请微信支付商户号（微信支付商户平台，1–3 个工作日）
2. 小程序后台 → 微信支付 → 商户号管理 → 关联商户号
3. 云开发控制台 → 云调用 → 微信支付 → 绑定商户号
4. 云函数 `pay` → 配置 → 环境变量 `WXPAY_MCHID` = 商户号
5. 云开发控制台 → 云调用 → 微信支付 → **支付回调**设为 `payCallback`

> 支付没配好也能先提审（下单会成功，支付环节提示"支付未配置"），但**正式开卖前必须配好**。

## 第 6 步：自测（真机，别只在模拟器点）

- [ ] iOS + 安卓各一台真机完整走一遍：浏览 → 加购 → 下单 → 支付（用 1 分钱商品测）
- [ ] 商家后台：发布商品 → 首页能看到 → 下架 → 首页消失
- [ ] 支付成功后：订单状态变"待发货"、库存扣减、销量 +1
- [ ] 断网 / 弱网下页面不白屏
- [ ] 首屏加载时间（目标 ≤ 1.5 秒）

## 第 7 步：上传代码

开发者工具右上角 **上传** → 填版本号（如 `1.0.0`）→ 备注（例：`首版：商品浏览、购物车、下单支付、商家后台`）→ 上传。

## 第 8 步：提交审核

小程序后台 → **版本管理** → 开发版本 → 提交审核。

**审核备注模板**（直接复制改）：

```
本小程序为商家自营电商平台，提供商品浏览、购物车、下单支付、订单管理功能。
测试账号说明：
1. 买家功能：任意微信用户打开即可浏览与下单，无需账号。
2. 商家后台入口：「我的」页 → 商品管理。因涉及经营数据，需管理员权限，
   审核人员如需查看，请在审核反馈中留言，我们第一时间开通体验权限。
3. 支付功能已接入微信支付，可用 1 分钱商品测试完整链路。
```

> 因为我们的商家后台要 `isAdmin: true` 才显示，审核员默认看不到——**必须在备注里说明**，否则可能以"功能无法体验"驳回。

## 第 9 步：发布

审核通过（一般 **1–7 天**，多数 1–2 天）→ 版本管理 → **发布**。发布后全量生效，可先选"分阶段发布"灰度观察。

---

## 常见驳回原因（提前避开）

| 驳回理由 | 规避方式 |
|---|---|
| 服务类目与商品不符 | 类目选「商家自营」，不卖需要许可证的品类 |
| 功能无法体验 / 缺少测试账号 | 审核备注写清楚，或临时给审核员开权限 |
| 诱导分享、强制授权 | 我们的分享是可选的，不要加"分享后才能用" |
| 虚拟支付 | iOS 端禁止虚拟商品支付，只卖实物 |
| 隐私协议未配置 | 第 4 步必做 |
| 名称含极限词 | 简介、商品标题避免"最好""第一""国家级" |

---

## 时间线参考

```
D0   注册企业主体小程序 + 发起备案 + 申请微信支付
D1-3 配置云开发、部署云函数、完善类目资质
D3-7 真机自测、上传代码、提交审核（备案通常此时已通过）
D7-10 审核通过 → 发布上线
```

## 上线后第一周建议做

1. 接**订阅消息**：支付成功后申请"发货通知"授权（代码里 `confirm` 页预留位置）
2. 配置**客服**：小程序后台添加客服人员，用户咨询能找到人
3. 看数据：小程序后台「数据分析」看访问、留存、转化
4. 补 SKU 和优惠券，再做增长玩法
