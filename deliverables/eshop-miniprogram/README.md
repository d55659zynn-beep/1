# 电商小程序 MVP（原生 + 微信云开发）

从「0 到能上架商品并卖出第一单」的完整骨架。

## 目录结构

```
eshop-miniprogram/
├── project.config.json
├── miniprogram/
│   ├── app.js            云开发初始化 + 全局登录态
│   ├── app.json          页面路由 / tabBar / 分包 / preloadRule
│   ├── app.wxss          全局样式
│   ├── sitemap.json      搜索收录（已全量放开）
│   ├── assets/tabbar/    tabBar 图标
│   ├── components/goods-card/
│   ├── utils/cloud.js    云函数统一调用 + 图片上传  
│   ├── utils/auth.js     登录态与金额换算
│   ├── pages/            主包：首页 / 分类 / 购物车 / 我的
│   └── subpackages/
│       ├── trade/        交易分包：商品详情 / 确认订单 / 支付结果 / 订单列表
│       └── admin/        商家后台：商品列表 / 发布编辑
└── cloudfunctions/
    ├── login        静默登录建档
    ├── product      商品列表/详情 + 后台增删改/上下架
    ├── cart         购物车
    ├── order        下单/订单列表/取消
    ├── pay          微信支付云调用统一下单
    └── payCallback  支付回调：改单、扣库存、加销量
```

## 一、跑起来（约 15 分钟）

1. **导入项目**：微信开发者工具 → 导入项目 → 选本目录 → 填你的 AppID（没有就选「测试号」）。
2. **开通云开发**：工具栏「云开发」→ 新建环境（按量计费有免费额度）→ 复制**环境 ID**。
3. **填环境 ID**：打开 `miniprogram/app.js`，把 `ENV_ID` 改成你的环境 ID。
4. **部署云函数**：在开发者工具里对 `cloudfunctions/` 下每个目录右键 → **上传并部署：云端安装依赖**，顺序：`login → product → cart → order → pay → payCallback`。
5. **建数据库集合**：云开发控制台 → 数据库 → 新建 `users`、`products`、`carts`、`orders` 四个集合。  
   权限全部设为 **「仅管理端可读写」**（所有读写都走云函数，防越权）。
6. 编译预览，首页应能正常打开（此时还没有商品，属正常）。

## 二、上架商品（3 步）

1. **开通自己的管理权限**：云开发控制台 → 数据库 → `users` 集合 → 找到你自己那条记录（先打开一次小程序，`login` 云函数会自动建档）→ 把 `isAdmin` 改成 `true`。
2. **发布商品**：小程序「我的 → 商品管理 → 发布」→ 填标题、售价、库存，上传至少 1 张图 → 打开「保存后立即上架」→ 保存。
3. **前台验证**：回到首页下拉刷新，商品已出现；点进详情可加购、下单。

后续在「商品管理」里可以一键 **上架 / 下架 / 编辑 / 删除**，库存和销量会随成交自动变化。

## 三、接微信支付

1. 云开发控制台 → 云调用 → 微信支付 → 绑定你的**微信支付商户号**（需企业主体）。
2. 云函数 `pay` → 配置 → 环境变量新增 `WXPAY_MCHID` = 商户号（也可直接改 `pay/index.js` 里的 `MCHID` 常量）。
3. 云开发控制台 → 云调用 → 微信支付 → **支付回调**设置为 `payCallback`。
4. 未配置支付也能跑通全流程：下单会成功，支付环节提示「支付未配置」，订单以「待付款」留存。

## 四、提审前检查清单

- [ ] 小程序类目选择「电商平台 / 商家自营」，并上传对应资质
- [ ] 在公众平台完善《用户隐私保护指引》，与本代码用到的 API 一致（当前只用了相册/相机，用于上传商品图）
- [ ] 提交审核时提供测试账号（或在审核备注说明管理端入口）
- [ ] 首页、商品详情页、下单页在 iOS 与安卓真机各走一遍
- [ ] 商品图用实拍或授权图，避免侵权

## 五、当前边界与下一步

已实现：商品 CRUD 与上下架、分类与搜索、购物车、下单、支付主链路、订单列表与取消。

未实现（按优先级建议）：

1. **SKU 规格**：当前只有单一价格与库存，多规格需加 `skus` 集合
2. **订阅消息**：支付成功后申请「发货通知」授权，回调时下发
3. **优惠券 / 新人券**：见架构文档中的 `coupons`、`user_coupons` 设计
4. **物流与售后**：对接快递查询、退款流程
5. **数据看板**：订单与商品维度统计
