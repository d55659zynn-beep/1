# 电商小程序架构设计（快速上线版）

> 目标：**3 周内上线 MVP，上线即具备获客与召回能力**
> 选型：原生小程序 + 微信云开发 + 全部四类增长能力（分享裂变 / 订阅消息 / 公众号联动 / 搜索优化）

---

## 1. 技术选型决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 渲染框架 | 原生（WXML/WXSS），核心列表页用 Skyline | 包体最小、新能力支持最快；Skyline 长列表性能显著优于 WebView |
| 后端 | 微信云开发（TCB） | 免服务器、免域名备案、免 HTTPS 证书、天然过 request 域名白名单，1-2 周可上线 |
| 状态管理 | 全局 `app.globalData` + 页面级 `setData` | MVP 阶段不引入 Mobx，减少复杂度 |
| 组件库 | 自研轻组件 + 按需引入 TDesign | 主包体积敏感，只引入用到的组件 |
| 构建 | 开发者工具 + npm（miniprogram_npm） | 原生链路最简单 |

**约束红线**：主包 ≤ 2MB（目标 1.5MB），总包 ≤ 20MB；所有网络请求走云开发 SDK，不碰域名白名单。

## 2. 项目结构

```
├── app.js                  # App 生命周期、全局数据、登录态初始化
├── app.json                # 页面路由、tabBar、分包、preloadRule、权限声明
├── app.wxss                # 全局样式与主题变量
├── sitemap.json            # 搜索收录配置（全部放开）
├── project.config.json
├── pages/                  # 主包：tabBar 四页
│   ├── index/              # 首页（爆款 + 活动入口 + 新人券弹层）
│   ├── category/           # 分类
│   ├── cart/               # 购物车（凑单提醒）
│   └── mine/               # 我的（资产/订单入口）
├── subpackages/
│   ├── trade/              # 交易分包（首访预加载）
│   │   ├── pages/product/  # 商品详情（分享卡片出口）
│   │   ├── pages/confirm/  # 确认订单（订阅消息授权点）
│   │   ├── pages/pay-result/
│   │   └── pages/orders/   # 订单中心/售后
│   └── marketing/          # 营销分包（按需加载）
│       ├── pages/groupon/  # 拼团
│       ├── pages/coupon/   # 优惠券中心
│       ├── pages/poster/   # 分享海报生成（canvas）
│       └── pages/vip/      # 会员/积分
├── components/             # 自研组件：goods-card、price、sku-picker、countdown、share-sheet
├── utils/
│   ├── cloud.js            # 云函数统一调用封装（Promise + 错误处理 + 埋点）
│   ├── auth.js             # 静默登录、手机号授权
│   └── track.js            # 事件埋点（微信自带分析 + 自定义事件）
└── cloudfunctions/         # 云函数（见第 4 节）
```

### app.json 关键配置

```json
{
  "pages": ["pages/index/index", "pages/category/category", "pages/cart/cart", "pages/mine/mine"],
  "subpackages": [
    { "root": "subpackages/trade", "name": "trade", "pages": ["pages/product/product", "pages/confirm/confirm", "pages/pay-result/pay-result", "pages/orders/orders"] },
    { "root": "subpackages/marketing", "name": "marketing", "pages": ["pages/groupon/groupon", "pages/coupon/coupon", "pages/poster/poster", "pages/vip/vip"] }
  ],
  "preloadRule": {
    "pages/index/index": { "network": "all", "packages": ["trade"] }
  },
  "tabBar": { "list": [ { "pagePath": "pages/index/index", "text": "首页" }, { "pagePath": "pages/category/category", "text": "分类" }, { "pagePath": "pages/cart/cart", "text": "购物车" }, { "pagePath": "pages/mine/mine", "text": "我的" } ] },
  "permission": { "scope.userLocation": { "desc": "用于展示附近门店与运费计算" } }
}
```

**要点**：`preloadRule` 让首页加载时后台预下载交易分包，用户点进商品详情零等待——这是分包体验不受损的关键。

## 3. 云数据库设计（集合）

| 集合 | 关键字段 | 索引 | 说明 |
|---|---|---|---|
| `users` | _openid, nickName, phone, inviter_openid, points, vip_level, created_at | _openid(唯一) | 静默登录即建档，`inviter_openid` 记录裂变来源 |
| `products` | title, cover, images, price, market_price, stock, sales, category_id, status, groupon_price | status+sales, category_id | 销量冗余字段，列表页免聚合 |
| `skus` | product_id, spec, price, stock | product_id | SKU 独立集合，避免商品文档过大 |
| `carts` | _openid, product_id, sku_id, quantity, checked | _openid | 每人≤120条 |
| `orders` | order_no, _openid, items[], total, status, address, groupon_id, prepay_id | _openid+created_at, order_no(唯一) | 状态机：待付款→待发货→待收货→完成/退款 |
| `coupons` | title, type, threshold, amount, valid_from, valid_to, status | status | 券模板 |
| `user_coupons` | _openid, coupon_id, status, expire_at | _openid+status | 到期前 1 天触发订阅消息召回 |
| `groupons` | product_id, leader_openid, members[], target, status, expire_at | status | 拼团实例 |
| `share_logs` | sharer_openid, scene, product_id, created_at | sharer | 裂变归因与邀请奖励结算 |
| `config` | key, value | — | 首页运营位、新人券开关、活动配置（免发版改运营） |

**权限**：全部集合设为「仅创建者可读写」或「所有用户不可读写（仅云函数可操作）」，读写一律收敛到云函数，防止越权。

## 4. 云函数清单

| 云函数 | 职责 |
|---|---|
| `login` | wx.login code → openid 建档/更新，返回用户信息 |
| `product` | 商品列表/详情查询（列表页带缓存） |
| `cart` | 购物车增删改查 |
| `order` | 下单（库存校验+事务扣减）、取消、确认收货 |
| `pay` | 统一下单（cloudPay.unifiedOrder）、**支付回调**（验签+更新订单+触发发货通知订阅消息+返积分） |
| `coupon` | 领券、核销、新人券自动发放、到期召回（定时触发器） |
| `groupon` | 开团/参团/成团判定（定时触发器处理超时未成团自动退款） |
| `share` | 分享归因记录、邀请奖励结算（被邀请人首单完成后发券） |
| `subscribe` | 订阅消息发送（发货/成团/券到期/降价提醒） |
| `admin` | 简易运营后台接口（商品上下架、订单发货、券配置） |

**安全**：支付回调必须验签；金额计算一律在云函数端完成，客户端价格永不信任。

## 5. 核心链路

### 5.1 登录与用户体系
1. 启动即 `wx.login()` 静默换 openid 建档，**不强制授权头像昵称**（新规范：进入即弹授权会被审核拒）。
2. 头像昵称：在「我的」页用 `<button open-type="chooseAvatar">` + 昵称输入框按需采集。
3. 手机号：下单环节用 `getPhoneNumber` 按钮触发，业务有明确用途，过审无风险。
4. 裂变归因：分享路径带 `?from=<openid>&scene=groupon`，新用户建档时写入 `inviter_openid`。

### 5.2 支付链路
```
下单(云函数事务: 验库存→锁券→建单)
  → cloudPay.unifiedOrder 返回支付参数
  → wx.requestPayment 调起支付
  → 支付回调云函数: 验签→更新订单→发订阅消息→加积分→结算邀请奖励
```
退款走定时/人工触发的 `admin` 函数调退款 API。

### 5.3 订阅消息授权时机（转化率最高的三个点）
| 时机 | 模板 |
|---|---|
| 支付成功后 | 发货通知、物流提醒 |
| 参团成功后 | 成团通知、拼团失败退款通知 |
| 领券后 | 优惠券到期提醒（到期前 24h 定时触发） |

`wx.requestSubscribeMessage` 一次最多 3 个模板，放在用户主动操作的成功回调里，不要启动时弹。

## 6. 增长能力落地

1. **社交裂变**：商品详情/拼团页实现 `onShareAppMessage` + `onShareTimeline`；拼团为 2 人团低门槛；邀请有礼 = 被邀请人首单完成，双方各得券（云函数结算，防刷：同设备/同 openid 限制）。
2. **订阅消息召回**：券到期、拼团结果、降价提醒三条主线，目标 7 日留存 ≥ 25%。
3. **公众号联动**：公众号关联小程序（同主体），菜单+推文插入小程序卡片；推文落地页直接是拼团活动页（营销分包）。
4. **搜索优化**：`sitemap.json` 全部放开；页面 `onShareAppMessage` 标题覆盖核心品类词；商品详情页配置 `wx.setPageMeta` 或页面 JSON 的 `navigationBarTitleText` 带商品词；开通「附近的小程序」（有门店时）。

## 7. 性能预算与优化清单

| 指标 | 目标 |
|---|---|
| 主包体积 | ≤ 1.5MB |
| 冷启动首屏 | ≤ 1.5s（中端安卓） |
| 单次 setData 数据量 | ≤ 256KB，非视图数据放 `this` 上 |
| 商品列表 | Skyline scroll-view + 分页 20 条 + 图片懒加载 |
| 图片 | 云存储 + image 组件 `lazy-load`，宽度不超 750rpx 展示尺寸，WebP |

优化手段：首页数据一次聚合云函数返回（减少往返）；商品详情首屏只传 5 张图；营销分包不进 preloadRule。

---

## 8. 审核避坑清单

- 电商类目：需「商家自营」或对应经营资质，提前在微信公众平台完善类目与资质。
- 不诱导分享（不写"分享后才能使用"），裂变激励用"邀请有礼"而非强制解锁。
- 隐私协议：提交前在 MP 后台完善《用户隐私保护指引》，代码内敏感 API（手机号、位置）用途必须与声明一致。
- 虚拟支付：iOS 端禁止虚拟商品支付——本方案为实物电商，无此风险。
- 分销层级不超过一级（只奖励直接邀请人），规避多级分销违规。

## 9. 三上线路线图

**第 1 周 · 骨架**：项目初始化 → 云开发环境开通（dev/prod 双环境）→ 登录建档 → 商品/分类/详情/购物车 → 下单 + 微信支付打通（含回调）。
**第 2 周 · 增长**：新人券 → 拼团 → 分享归因 + 邀请有礼 → 三类订阅消息 → sitemap + 公众号关联 → 简易运营后台（云函数 + 云数据库控制台）。
**第 3 周 · 收口**：性能优化（分包、预加载、图片）→ 真机测试（iOS/安卓/弱网）→ 隐私指引与类目资质 → 提审（预留 1-7 天审核期）。

**上线后迭代**：会员积分体系（营销分包已预留 vip 页）→ 数据分析复盘（留存/分享率/首单转化）→ 视频号挂载 → 企业微信社群承接。
